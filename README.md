# НеКрапива

Дневник контроля крапивницы и отёков. Автор — Коршунов Максим Александрович.

Первая реализация приложения: отдельные пациенты, суточные записи, эпизоды отёков, назначения с историей изменений, фактические приёмы препаратов, фотографии, наблюдения за обстоятельствами, отчёт врачу и локальные резервные копии. Пять основных разделов: Сегодня, Контроль, Дневник, Факторы, Памятка.

## Запуск

Приложение статическое; серверная база данных и регистрация не используются. Открывайте через HTTP на localhost или HTTPS, а не двойным щелчком по index.html.

```sh
python -m http.server 4173 --bind 127.0.0.1
```

Адрес для локальной проверки: http://127.0.0.1:4173/.

## Сборка и публикация

```sh
python -m venv .venv
. .venv/bin/activate
pip install -r requirements-build.txt
python tools/build.py --url https://maksimkorsunov259-lab.github.io/ne-krapiva/
```

Готовые файлы приложения находятся в корне репозитория и включены в Git. Сборка обновляет их и дополнительно создаёт `dist/` для отдельного переноса. QR-код генерируется локально для указанного адреса.

Публикация настроена по той же схеме, что у остальных приложений семейства:

1. Settings → Pages → Build and deployment → Source: **Deploy from a branch**.
2. Branch: **main**, папка **/ (root)** → **Save**.
3. Дождаться успешного системного запуска **pages build and deployment**.

Файл `.nojekyll` в корне отключает преобразование готовых файлов через Jekyll. Собственный workflow `check.yml` только проверяет приложение и не публикует сайт. Прежний `pages.yml` удалён; если его старый запуск ещё в очереди, отмените его в Actions через меню запуска → Cancel workflow.

Адрес приложения после успешной публикации: https://maksimkorsunov259-lab.github.io/ne-krapiva/. Отдельный домен и файл CNAME не требуются.

Версия меняется в package.json. Затем повторяется сборка; хеш содержимого создаёт новую версию кэша. Опубликованный адрес должен быть постоянным: хранилище привязано к origin браузера и пути приложения. Перенос на другой адрес требует JSON-копии.

## Данные

IndexedDB: `ne-krapiva:<путь приложения>:v1`. Метаданные и фотографии записываются одной транзакцией. Перезапись проверяет ревизию базы, чтобы обнаруживать изменения в другой вкладке. Приложение подтверждает сохранение только после завершения транзакции. При ошибке данные не сбрасываются.

Дневники отдельных пациентов разделены идентификаторами. Назначение сохраняется новой версией, а фактический приём хранит снимок выбранного назначения. Пропущенные ответы и дни не заменяются нулём. Черновики основных форм сохраняются на устройстве; черновик нового профиля и несохранённые файлы фотографии не входят в резервную копию.

JSON включает выбранных или всех пациентов и по умолчанию фотографии. Импорт проверяет структуру, ссылки на пациента и изображения до единой транзакции. Можно добавить отдельные дневники либо явно заменить совпадающие идентификаторы. PDF содержит сводку и все записи периода; фото только по выбору пользователя. PDF сохраняется через системное окно печати.

Нет аналитики, сторонних шрифтов, серверной отправки медицинских записей или фонового обмена дневником. Внешние ссылки автора открываются по нажатию. Хранилище браузера не является гарантированной резервной копией и не зашифровано самим приложением; доступ к устройству следует защищать.

## Инструменты первого выпуска

Подключены UAS за 24 часа/UAS7, UCT за 4 недели, AAS за сутки/AAS7/AAS28, AECT за 3 месяца и отдельная рабочая адаптация за 4 недели, AE-QoL. Возраст и показания применяются по согласованной автором политике. Порог 4 года для UAS7/UCT — проектное решение, не заявленный установленный минимум валидации. В педиатрии сохраняются ограничения интерпретации и способа заполнения. Неизвестный возраст не разрешает автоматический расчёт.

PedsQL Parent Proxy, CDLQI, UCT7, CU-Q2oL, ColdUAS, CholUAS7 и DLQI отложены по решению автора: в интерфейсе нет имитации их форм или расчётов. Их реестр сохранён в `docs/future-instruments.json` для последующего дополнения.

Тексты — рабочие русские адаптации по предоставленному автором сборнику, а не заявление об официальном переводе или независимой клинической валидации. Источники, формулы, версия языка и сведения о применимости доступны в реестре и экране «Об инструменте». Решение о разрешении использования сторонних инструментов принимает правообладатель приложения; наличие исходников не означает свободную лицензию на сторонние материалы.

## Проверка

```sh
npm test
pip install playwright
# Нужен установленный Chromium (/usr/bin/chromium).
python tests/browser.py
```

Браузерные проверки запускают временную копию приложения и используют только синтетические записи. Проверяются сохранение/перезагрузка, черновики, несколько пациентов, возрастная маршрутизация, формулы, фотографии, PDF, импорт JSON, конфликты записи, ошибка хранилища, работа без сети и обновление без потери данных.

Настоящую установку нужно дополнительно проверить на Android/Chrome и iPhone/iPad/Safari по опубликованному HTTPS-адресу. Проверка настольного Chromium не заменяет проверку на физических устройствах.
